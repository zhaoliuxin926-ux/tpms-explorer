# 水密 ≠ 正确（两次）：一根杆从胶囊 SDF 到上机试样的全链实录

> 数字与命令均可在本仓库复现：`node tpms/agent/tpms.mjs <command>`（下文每条命令今天都真实跑过一遍）；门禁断言在 `tpms/.verify/`（schema_check 113 断言含 strut 双族枚举；nl_agent 48 断言含桁架词表；文档数字一致性门 349 断言守着本文这类宣称）。系列前三篇：《[44 道门禁](https://juejin.cn/post/7691244760439439414)》《[LLM Agent 的安全架构](https://juejin.cn/post/7692881705648685097)》《[WGSL 从未被执行过](https://juejin.cn/post/7692977150127259711)》——本篇是"验证方法论"在几何扩展上的一次完整落地。写作时平台为 v9.2.0（24 族）；发布时已升级 v9.3.0-strut-pareto（26 族+Pareto 逆设计+画廊），文中全部命令口径不变。

## 起点：24 族曲面里没有一根直杆

TPMS Explorer 运行两年，24 族全是隐函数周期曲面——gyroid、diamond、neovius……骨支架文献里反复出现的另一半世界却始终缺席：**桁架**。BCC 桁架（体心立方，杆件受弯）与 Octet 桁架（面心立方，杆件受拉）是点阵力学对照的经典命题——弯曲主导的刚度按相对密度平方衰减（E\*∝ρ̄²），拉伸主导按线性衰减（E\*∝ρ̄）——谱系的两极都在文献里，不在平台上。

平台需要一个桁架族。问题：一个为隐函数曲面设计的系统，怎么装进"一根根杆"？

## 架构红利：胶囊 SDF 塞进 TpmType

答案是几乎不需要动架构。TPMS 族的场函数签名是 `f(x,y,z,weights)` 返回标量场，等值面提取器吃任何标量场。而杆 = 线段的有符号距离函数（胶囊体）：到线段最近点的距离减去杆半径。把 BCC 晶格的杆端点写成周期延拓坐标，整族杆阵就是一个标量场——负值区是固相，iso 值即有效杆径。

于是求解器（按目标孔隙率二分 iso）、等值面重建、水密 STL 导出、渗透率/比表面积分析、自然语言词表——**全部零改动自动支持**。CLI 一条命令：

```bash
node tpms/agent/tpms.mjs mesh --type strutbcc --porosity 0.7 --out bcc.stl --json
# 实测（真 BCC 桁架场，periods 6 / resolution 64）：水密 openEdges=0，283,092 三角，13.5MB，
# 网格实测孔隙率 0.7019（与目标差 0.19pp），solver=exact
```

（为什么示例换成了 BCC：Octet 的真拓扑在水密门当时是结构化拒产——下文第四个坑，以及它一周后的解锁结局。）

"几乎"两个字里藏着后面所有坑。

## 第一个坑：水密掩盖的几何错位

首版 strutbcc 交付时全绿：水密 True、渲染正常、孔隙率达标。两周后一个坐标域复查戳穿了它——场函数收到的 `mx=[−1,1]×k` 是**弧度域坐标**，而杆端点表是按几何域 `[−1,1]` 写的。两套坐标差一个缩放因子，杆阵整体错位：该在角上的杆跑到了错误的位置，但错位后的几何依然是一坨自洽、水密、可渲染的"某种结构"。

这是本项目第三次撞上同一句话：**水密 ≠ 几何正确**。水密自检回答"这个网格封闭吗"，从不回答"这是你想建的那个结构吗"。

当时以为正解很优雅：杆端点改在弧度域直接周期延拓，UI 三角数随 k 单调（17.6k→72k→217k）——拓扑真的在变密。修复上线，全绿交付。

**一个月后，外部审计戳穿了第二层：上面这些"全绿交付物"依然不是桁架。** 等值面提取器里有一个为经典 sin/cos 族做的查表快路径，新族注册时要在排除清单里登记才会走实时求值分支——strut 双族漏登了。于是体素场静默走了查表链的兜底公式，那条公式是 **Schwarz P** 的。铁证荒诞到好笑：同参数下 strutbcc、strutoctet、schwarz 三个命令产出的三角数**逐位相同**（98,064）——此前所有"桁架"STL、试样、基准数字，实为"投影用了真杆场、提取用了 schwarz 场"的嵌合体。水密依然 True，渲染依然正常，孔隙率依然达标。

**第四次撞上同一句话，也是最深的一次**：错误不在杆的数学里，在"新族接入快路径"的分派链上——而门禁只数了族枚举，没数分派。修完之后我给这类事故立了三根钉子：提取器排除清单进静态哨兵；mesh 顶点必须落回真场（残差 4e-7，嵌合体在这条断言下必红）；同参数跨族三角数分化进回归（逐位相同=嵌合体签名）。

## 第二个坑：词表的子串劫持

自然语言入口的族名匹配是 first-match 子串。strutoctet 上线后，用户输入"用 Octet 桁架建一个支架"，命中链走到裸"桁架"（已注册为 strutbcc 的同义词）就停了——**"Octet 桁架"里的"桁架"把前面的限定词劫走了**，建出来的是 BCC。这是该词表第三次犯同型错误（前两次：Double Diamond 被 diamond 劫持、"单元密度"用户照界面说话解析不了）。

修法同前：具体变体前置（"Octet 桁架"排在裸"桁架"之前）。但三次同型错误值得说破：**first-match 子串匹配是有结构性缺陷的架构选择**，修一次躲一次不叫根治——词表每加一个"泛指+特指"对，就要人工排一次序。回归集补了三条真实用例（B7/B8/C8），双轮 40/40 全过才放行。

## 第三个坑：注册链的最后一环没有门

26 族上线后的一次跨族 undo/redo 走查发现：**strut 双族在 UI 里根本选不到**。族注册清单走遍了 types/颜色/权重/函数表/WGSL/URL/词表/CLI/schema 枚举——每一处都有断言网盯着，唯独漏了 UI 按钮区：`index.html` 的 type 按钮是手写的静态资源，不是 `Object.keys` 动态生成；而 ui_jump 门禁只数折叠组，不数组内按钮。

用户只能靠 URL 参数进这两族。门禁驱动注册的网眼，就是门禁自身的覆盖面。修法是补一个折叠组+改绑定为 `querySelectorAll('[data-type]')` 动态匹配——此后按钮区与族注册表结构上无法再脱钩。

## 力学标定：不硬拟合的诚实

桁架族的力学代理走 Gibson-Ashby 开孔泡沫律 E\*/Es=C1·ρ̄²。两族的标定结果是一堂对照课：

- **strutbcc：C1=0.06**——落在 Despande-Fleck BCC 弯曲主导文献域的中值，ρ² 律与 BCC 的力学故事完全适配。
- **strutoctet：C1=1.2**——但 Octet 是拉伸主导，**真实律是线性的，形状上不适配 ρ² 框架**。C1=1.2 实为 ρ̄≈0.25 附近的等效切线；源码披露它偏离该密度时漂移可达 2×，精确值走有限元。

```bash
node tpms/agent/tpms.mjs estimate --type strutbcc --porosity 0.65 --json
# 实测：C1=0.06 / C2=0.3 / anisotropy=1（立方对称），
# E*=0.81GPa@ρ̄=0.35（Ti-6Al-4V）——弯曲族的柔性直觉有数了
```

诱惑是把 1.2 也当成"标定成功"写进文档。没有这样做。一个月后 M5 工业链全流程实测验证了这个决定：octet 支架 E\*=16.17GPa，超出文献带 [4.7,5.9]——**这正是标定时披露的线性律形状偏差在真实交付链上的现形**，验证报告里预埋的诚实边界条款直接解释了它，而不是留给用户猜。

## 全链验收与 32 件试样

最后一块拼图是真场修复后的交付链。真实 LLM（glm-5.3-flash）一句话 → 工具选择 → **确定性管线**（推荐→候选选取→构建→水密验收→悬垂可打印性报告）一步到位；有趣的是管线的修复预算顺延在真实数据上第一跳就派上用场：E≥2GPa 的首推荐是 Octet——水密门结构化拒产（exit 3，无 STL 交付）——管线自动顺延第二候选 diamond，构建水密 0.18pp，全程 47 秒报告三层口径分明（代理推荐是解析近似非 FE、网格验收是实测、可打印性是工程阈值）。

试样矩阵重做：**S7（strutbcc）四件真场重生成**——水密、孔隙率 0.6519（偏差 0.19pp，嵌合体旧件是 4.4pp）、四件逐位确定 41MB/件；旧嵌合体件整体归档并标注"不得上机"。**S8（strutoctet）受阻披露**：真 Octet 拓扑的 12 杆结点在单顶点/胞等值面提取下结构性非流形（全分辨率/杆径域实测无水密窗），CLI 水密门 fail-closed 拒收、零破网格交付，试样协议里留下一份结构化拒产记录（非流形边 190,656）作为边界证据——当时判断根治需要提取器支持多片共胞，已立项（一周后这个判断被证伪，真因不是拓扑——见下节）。

## 第四个坑的结局：不是拓扑，是焊接（2026-10-12 解锁后记）

上文的受阻结论只活了一周。立项的 MC33 拓扑路线先行证伪：胞级（固相,空气）分量对拆分确实能把非流形边 4,050→0，但鞍点面邻胞分解不一致，撕裂出约 5 万条开放边；事后片层分离是 no-op（界面经 2-共享边连通，本来就是单组件）；细杆全径无逃逸域。三个拓扑假说全死在数据上。

真因来自逐边解剖：内部 4-共享边的"两端"其实是**同一个物理点**——Newton 投影把薄 feature 两侧的胞质心拉到了同一个表面点，全部 4,050 条非流形边都是亚格距短边（中位长度约 h/7）。既然两端是同一个点，这就是**投影重合的焊接问题**，不是拓扑缺陷。

修法因此收敛为一个 surface-nets 焊接块（仅 strut 族门控）：只焊使用次数 ≠2 的边——流形边永远不动；每轮批量焊全体候选（union-find 合链）迭代至收敛（探针逐边版 602s，内核批量化后秒级）。焊接位移的定量上界尚未证明（union-find 链式合并的位移传播不在本篇证据内），已交付的是行为证据：Octet k3/R48 非流形 4,050→0（焊接 4,096），k6/R64、k8/R96 全部开放边=0、非流形=0；已测范围内 BCC sha256 字节级不变（S7 四件试样与基准矩阵 R48/R96——非流形=0 时焊接零操作，S7 免重生成仍有效；未穷举全部参数域）。S8 四件重生成：水密、孔隙率偏差 0.88pp、42.2MB、逐位确定。32 件试样至此全部通过当前网格交付检查（水密门），具备进入打印验证的条件；桁架 vs TPMS 的 E 对照补齐了 Octet 这一极。

边界同样如实：焊接候选没有长度门限、union-find 链式合并的位移传播无定量上界证明（均已登记——试样未因此被证伪，但几何保真宣称需要独立的焊接位移/连通性/真场残差验证支撑）；解锁还连带暴露了错误路径回归的空洞——旧测试靠"Octet 恰好拒产"验证不可达链，解锁即失效，后续以可控故障注入补齐（可替换执行器夹具，不再依赖任何几何族"恰好不可产"）。

## 可迁移清单

1. **标量场是最低公约数接口**：新几何族以"距离场函数"接入，下游全部环节零改动——前提是你能忍住不为它开后门。
2. **水密/渲染/孔隙率全绿 ≠ 几何正确**：验收断言要钉"拓扑随参数单调变化"这类结构性质，而不是只钉网格健康度。
3. first-match 子串词表每收一个泛指词就欠一笔排序债；特指前置是止血，真实用例进回归集才是证据。
4. 门禁驱动注册的网眼=门禁自身覆盖面：静态资源（手写按钮、手写清单）是断言网照不到的暗区。
5. 标定前先问"模型形状对不对"，再问系数准不准——形状不适配时最好的系数也只在一点上成立；把披露预埋进交付物，偏差现形那天它替你解释。
6. **新族接入快路径时，分派链就是产品**：排除清单漏一行，交付的就不是你以为的几何；给分派立静态哨兵、给网格验"顶点落在真场上"，比事后全绿更接近真相。
7. **"结构性不可产"的结论要先解剖再立项**：三个拓扑假说全死在数据上——4-共享边两端是同一个物理点（投影重合），修的是焊接不是拓扑；修复面的验收选"对不该动的对象零操作"（已测范围内 BCC 字节级不变是最好的证词），错误路径的回归别押在任何一族"恰好失败"上。
