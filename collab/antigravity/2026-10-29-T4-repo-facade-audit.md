## 二、问题清单（按严重度排序）

### P0 级：严重损害专业度或存在事实性矛盾的硬伤

#### 1. 【事实漂移】`README_EN.md` 自证段残留 `46-gate badge` 旧数据
- **文件与行号**：`README_EN.md:96`
- **问题现象**：
  ```markdown
  The 46-gate badge is not a claim — these two commands let you watch the gate suite audit itself.
  ```
  在文件开头宣称是 `48 CI gates`（Line 8），但在自证代码段下方却写成了 `The 46-gate badge`（中文版对应行为 `48 门不是徽章嘴说的`）。
- **影响**：外企招聘官或海外审稿人阅读英文文档时，一眼会识破前后数字矛盾，直接质疑门禁宣传的真实性。
- **依据**：`tpms/.verify/run_ci_suite.mjs` SCHEDULE 实测为 48 门；`docs_consistency_check.mjs` 曾设置禁词规则，但仅禁了 `45-gate`，遗漏了 `46-gate` 哨兵。
- **整改建议**：将 `The 46-gate badge` 修正为 `The 48-gate badge`（不破坏门禁数字锚点，且与 48 对齐）。

#### 2. 【排版硬伤】`docs/QUICKSTART.md` Demo 编号逻辑严重跳跃
- **文件与行号**：`docs/QUICKSTART.md:5-55`
- **问题现象**：
  标题顺序依次为：
  - `## Demo 1 · 网页点选（最短）`
  - `## Demo 2 · CLI 一行（可脚本化）`
  - `## Demo 4 · 逆设计一行`（跳过了 3）
  - `## Demo 5 · Agent 会话两步走`
  - `## Demo 6 · 一步到位管线`
  - `## Demo 3 · 自然语言 Agent`（3 被扔到了 6 后面！）
- **影响**：访客在阅读快速开始时会产生“文档经过多人随意粘贴、缺乏基础校对”的粗糙感，严重影响审稿人与招聘官对项目严谨度的打分。
- **整改建议**：按用户认知深度重排编号（1 网页 $\to$ 2 CLI $\to$ 3 逆设计 $\to$ 4 自然语言 Agent $\to$ 5 Agent 会话 $\to$ 6 完整管线），或统一调整为 1~6 连续编号。

#### 3. 【定位卖低】`README.md` 根标题无项目名，且首屏定位矮化为“教学工具”
- **文件与行号**：`README.md:1, 28-30`
- **问题现象**：
  - 根 README 的 H1 标题竟然是 `# 工作区 · 总导航`！新访客点进仓库，第一眼看不到项目名称 `TPMS Explorer`。
  - 正文介绍写道：“可交互的三重周期性极小曲面（TPMS）教学工具，帮初学者快速入门”。
- **影响**：在 GitHub 首页黄金 5 秒内，合作者或审稿人会误认为这只是一个给本科生入门课程写的科普 Toy-Project，直接劝退寻找科研级/工业级工具的高价值用户。
- **对比**：`README_EN.md` 开头即为 `# TPMS Explorer — Interactive Triply Periodic Minimal Surfaces`，并紧随一句极其硬核的提炼：“What makes it different: a verification-first culture. Every formula, mesh and export path is guarded by 48 CI gates...”。
- **整改建议**：
  - H1 统一提升为：`# TPMS Explorer · 三周期极小曲面结构探索器与多物理场数字孪生平台`；
  - 首屏一句话提炼：“以严苛验证为底座（48 道 CI 门禁、1000+ 断言）的交互式 TPMS 结构参数探索器，覆盖设计、力学/流体仿真、水密打印到 AI Agent 闭环全链路。”

### P1 级：削弱说服力、造成导航流失或认知混乱的设计问题

#### 4. 【导航分裂】“父子双 README”导致项目中枢认知脱节
- **文件与行号**：`README.md:28-30` 与 `tpms/README.md`
- **问题现象**：根 `README.md` 告诉用户“完整项目已归入独立子目录 `tpms/`，请直接看 `tpms/README.md`（项目中枢）”，但同时根 `README.md` 却保留了长达 50 行的特性矩阵大表。
- **访客困惑**：访客不知道应该停留在根目录阅读，还是应该点进 `tpms/`；当访客进入 `tpms/README.md` 后，又看到另一套结构类似的文档。
- **整改建议**：
  - 明确“根 `README.md` = 面向外部世界的产品橱窗与快速上手总入口”；
  - `tpms/README.md` = 面向开发者的工程源码中枢；并在根目录显著标注两者的受众分工。

#### 5. 【王牌深埋】`BENCHMARKS.md` 与 `HONESTY_BOUNDARIES.md` 缺乏顶级视觉权重
- **文件与行号**：`README.md:11-23, 105`
- **问题现象**：
  - 本项目最能打动导师、审稿人和资深技术专家的两份资产：
    1. `BENCHMARKS.md`：26 族曲面的真实可产性、水密率、孔隙率偏差公开实测矩阵（杜绝学术画饼）；
    2. `HONESTY_BOUNDARIES.md`：15 条定案的诚实边界表（从 S3 采样信息论边界到微观 FEA 剪切上界，坦诚披露软件极限）。
  - 但在首屏的「文件导航（我该点开哪个？）」大表中，**这两份文件甚至没有独立占有一行**，而是被埋在第 105 行的一长串超链接文本之中。
- **整改建议**：
  - 在首屏导航表中增加专属行：
    `| ⚖️ 严谨性与学术诚信 | docs/HONESTY_BOUNDARIES.md（15条定案诚实边界）· BENCHMARKS.md（26族可产性公开基准） |`
  - 这种反常识的“主动晒边界”会瞬间拉满审稿人和资深工程师的信任度。

#### 6. 【链接拥挤】三屏速览后的超链接严重堆叠
- **文件与行号**：`README.md:39`
- **问题现象**：
  在短短一行文字里塞入了 9 个链接：
  `技术博客：[《44 道门禁》 ｜ [《安全架构实录》 ｜ [《你的 WGSL》 ｜ 📺 操作演示正片：[B 站 104s] ｜ 在线入口：[落地页] ｜ [教学版] ｜ [工程版]`
- **影响**：视觉缺乏呼吸感与焦点，最重要的在线体验入口（落地页/工程版）混在博客链接里，容易被忽略。
- **整改建议**：
  拆分为两行清晰的行动号召（Call-to-Action）：
  - **🚀 在线即用（零安装）**：[落地页 (Feature Tours) ｜ [工程工作站 (推荐) ｜ [教学版 (8经典族)
  - **📺 深度解读与视频**：[B 站 104s 演示 (BV1hVeS6jEBM) ｜ [技术博客专栏

### P2 级：前沿成果与高阶技术亮点缺失

#### 7. 【学术与工程前沿隐形】`sim/` 高保真仿真管线未在门面露出
- **现象**：
  当前 `README.md`、`PROJECT_SUMMARY.md` 对力学与流体仿真的描述依然停留在“体素级 C3D8 INP 导出”与“结构化六面体 OpenFOAM polyMesh”。
  然而，仓库近期已在 `sim/` 目录下实打实打通了：
  - `sim/p0_generate.py`：基于隐式场与坐标系外扩的高保真 STL 生成（孔隙率偏差仅 $0.02\text{pp}$）；
  - `sim/p1_mesh.py`：Gmsh HXT discrete 二阶四面体（C3D10，21 万单元，$\text{minSICN} > 0.057$ 零翻转）；
  - 严格兼容 `fit-batch.mjs` 契约的 ABAQUS 压缩模拟全闭环（实现仿真与物理试验同内核反演）。
- **建议**：在 `README.md` 的特性矩阵或进阶章节，增加“高保真 FEA/CFD 贴体网格自动化管线（`sim/`）”的概括介绍，让同行看到本项目不仅有浏览器轻量估计，更有工业级求解管线。

#### 8. 【工程方法论未露出】`collab/` 多 Agent 黑板异步协作体系未提及
- **现象**：
  仓库内正在高效运行的 **ZCode（主控）× 反重力（评审）** 多 Agent 异步黑板协作机制（`git-as-blackboard`、协议化任务认领、非接触代码评审、fail-closed 门禁裁决）具有极高的前瞻性，是顶尖 AI 研发与工程团队梦寐以求的实践范例。
- **建议**：在 `tpms/README.md` 或开发辅助章节，以一句话点出：“支持多 Agent 异步协议化协同研发体系（`collab/` 黑板模式）”，极大强化技术极客与前沿 AI 探索者的认同感。

#### 9. 【国际化断层】深度核心文档缺乏英文对照
- **现象**：
  `README_EN.md` 虽然整体行文流畅、英式/美式工程表达专业，但其中大部分快速链接（如 `docs/QUICKSTART.md`、`docs/PROJECT_SUMMARY.md`、`docs/WORKFLOW_GUIDE.md`）只有中文版。海外访客点开即陷入全中文长文，体验断层。
- **建议**：优先为 `docs/QUICKSTART.md` 补全 `QUICKSTART_EN.md`，保障海外访客“5 分钟出第一个 STL”的最小闭环。
