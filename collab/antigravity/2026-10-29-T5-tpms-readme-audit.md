## 三、问题清单（按严重度排序）

### 🔴 P0 级：严重结构脱节、误导开发者或破坏工程权威性的问题

#### 1. 【目录树严重失真】核心模块缺失与陈旧路径残留
- **位置**：`tpms/README.md:52-74`（`## 目录结构`）
- **现象事实**：
  1. **核心组件遗漏**：目录树中竟然没有列出 `tpms/agent/`（全平台的 AI Agent CLI、`tpms.mjs`、`llm-agent.mjs` 全在此处，第 16 行刚大篇幅介绍，下方目录树却直接漏掉！）；
  2. **物理路径过时**：树中写 `├── agent_memory/ ← 项目记忆...（gitignored）`，但仓库中的 `agent_memory/` 早在多设备定案时已迁移至**仓库根目录**（`agent_memory/`）并入库跟踪；
  3. **虚假目录残留**：树中列出的 `└── .zcode/ ← 计划文件（gitignored）` 在物理磁盘上**根本不存在**（实测返回 False）；
  4. **工程版源文件数滞后**：Line 69 标注 `87 个源文件`，实测 `tpms/tpms-platform/src` 下已有 **94 个文件**；
  5. **全局前沿视野缺失**：根目录近期构建的 `sim/`（高保真仿真管线）与 `collab/`（多 Agent 黑板协作）完全无体现。
- **影响**：任何严肃阅读代码的开发者或招聘官，根据该目录树对照实际仓库，会立即发现大量目录对不上，严重削弱工程中枢的权威度。
- **整改建议**：重构该目录树，准确反映当前仓库真实的模块组织结构（见第四章参考补丁）。

#### 2. 【受众与内容严重错位】陈旧截图与单文件版科普占据中枢篇幅
- **位置**：`tpms/README.md:94-118`（`## 界面预览`）及 `tpms/README.md:143-150`（`## 核心能力（单文件版）`）
- **现象事实**：
  - 作为“工程版中枢”，文档用近 50 行的篇幅放置了 7 张早期的前端 UI 截图（新手引导、公式演示、主界面、浅色主题...），并在第 143 行详细列出“单文件版核心能力（8 类曲面、公式权重交互、教学六层）”；
  - 事实上，单文件版早已被官方声明为**功能冻结的教学版本**（新特性已全部收敛至工程版 `tpms-platform/`）。
- **影响**：开发者点进工程中枢，期望看到的是 WebGPU 管线、TS 状态机、CLI 自动化、离线门禁，结果扑面而来全是教学演示截图。既挤占了开发文档空间，又造成了主客颠倒。
- **整改建议**：
  - 彻底剥离 7 张前端教学截图与单文件版特性展开（引导至 `../docs/app.html` 或 `../docs/LEARNING_PATH.md`）；
  - 将宝贵篇幅留给工程版实际架构：`tpms-platform/src/{core,geometry,physics,export}` 模块职责与数据流向。

#### 3. 【数字滞后漂移】工程版曲面族数误写为 24 类（应为 26 族）
- **位置**：`tpms/README.md:84`
- **现象事实**：
  ```markdown
  | **曲面族** | 8 类经典（教学聚焦） | **24 类**（C2 扩展含 Fischer-Koch / Double / Complementary D / Slotted P / F / Q* / W 等） |
  ```
  对比根 `README.md:58`（`26 族曲面（24 TPMS + 2 桁架）`）与 `docs/PROJECT_SUMMARY.md:12`（`工程版扩至 26 族（24 TPMS 隐函数 + strut 双族 BCC/Octet 桁架...）`），`tpms/README.md` 漏计了 2 族桁架，依然停留在旧的“24 类”描述中。
- **影响**：不同层级文档在基础能力数字上出现分裂，给审稿人留下“文档更新未同步”的硬伤把柄。
- **整改建议**：同步更新为 `**26 族**（24 TPMS + 2 桁架 BCC/Octet）`。

#### 6. 【命令执行环境混淆】缺失工作目录（cwd）显式声明

  - Line 176-179：
    ```bash

    ```

- **整改建议**：在所有命令块前统一定义基准路径（如“以下命令均在仓库根目录执行”），消除路径上下文歧义。
