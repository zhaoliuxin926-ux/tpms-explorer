## 二、核心关注点评审结论

### 关注点 ①：R24 分辨率下孔隙率偏差 1.14pp 的来源与收敛速度

#### 1. 偏差来源的定量拆解（实测数据支撑）
针对基准算例（$k=2, R=24, \text{margin}=2, p_{\text{target}}=0.60$），实测孔隙率偏差为 $+1.14\text{pp}$（目标 $60.00\%$，实际 $61.14\%$）。经反重力分步实测与数值解析，该偏差由三层误差叠加产生：

```
目标固相率 40.00%
  │
  ├─ [误差 1: 盒域非整数周期截断与相移] ── 固相率在盒内理论值偏离至 39.67% (+0.33pp 偏差)
  │     └─ 根源：ax 被锁在 [0, 2πk]，盒内缩至 [margin/n, 1-margin/n]，实际周期仅 1.846 周期！
  │
  ├─ [误差 2: 离散点计数 vs Marching Cubes 线性插值曲面积分] ── MC 网格固相率降至 39.10% (+0.57pp 偏差)
  │     └─ 根源：0 阶阶跃抽样 vs 1 阶线性插值多面体截交曲率截断误差 O(Δx²)
  │
  └─ [误差 3: pymeshfix 缝合与去自交] ── 剔除 1930 个面，体积减少 3.705 mm³ (+0.24pp 偏差)
        └─ 根源：折叠退化面修复时对边界折痕几何产生侵蚀

  => 最终固相率 38.86% (对应孔隙率 61.14%，总偏差 +1.14pp)
```

- **误差 1（核心结构性误差，约 0.33~0.90pp）**：
  在 `p0_generate.py` 第 63~68 行：
  ```python
  n = k * R + 2 * margin                     # 52
  ax = np.linspace(0.0, 2.0 * np.pi * k, n + 1)
  box_lo = 2.0 * np.pi * k * margin / n      # 0.4833 rad (约 27.7°)
  box_hi = 2.0 * np.pi * k * (1 - margin / n)# 12.083 rad
  ```
  `ax` 跨度为 $[0, 2\pi k]$，但盒子在 `ax` 内部收缩，导致：
  1. 盒子内部的有效周期数只有 $k_{\text{eff}} = 2 \times \frac{48}{52} \approx 1.846$ 个周期，根本不是预期的 $k=2$ 整数周期！
  2. Gyroid 等值面的体积分数在数学上仅在整数周期域（或其对称子域 $[0, \pi]$）上严格守恒。在任意截断相位（如 $27.7^\circ$）截断时，盒子内部的固相体积分数天然与全域平均值存在偏差。
  3. `solve_level` 是在包含全部 $[0, 2\pi k]$ 完整周期的全域网格上用 `mean(f >= mid)` 计算二分阈值 $c$ 的，而几何裁剪却截取了局部非对称的 $1.846$ 周期！

- **误差 2（离散表示截断误差，约 0.30~0.57pp）**：
  `solve_level` 使用的是采样点上的阶跃指示函数均值（0 阶 Riemann 积分）；而 `skimage.measure.marching_cubes` 是在每个体素立方体棱上做 1 阶线性插值求解 $g=0$ 并构建三角面片。对于马鞍面等高曲率 TPMS 几何，平面三角面片逼近双曲面存在固有的 $O(\Delta x^2)$ 几何逼近截断误差。

- **误差 3（清洗几何侵蚀，约 0.24pp）**：
  原始 MC 网格体积 $V_0 = 610.2228$（孔隙率 $60.90\%$，偏差 $0.90\text{pp}$）。经过 `process(validate=True)` 及 `pymeshfix` 修复后，体积缩水至 $V_2 = 606.5181$（$\Delta V = -3.7047$，体积分数丢失 $0.61\%$），直接导致孔隙率进一步从 $60.90\%$ 漂移至 $61.14\%$（新增 $0.24\text{pp}$ 偏差）。

#### 2. 收敛速度与 $R \to \infty$ 预期行为
- **当前实现的收敛率：**
  由于盒子截断占比为 $\frac{\text{margin}}{n} = \frac{\text{margin}}{k R + 2\text{margin}} = O(R^{-1})$，非整数周期截断的相移误差以 $O(R^{-1})$ 慢速衰减；MC 三角化曲面体积误差以 $O(R^{-2})$ 衰减。
  - 实测当前实现：$R=16 \to 1.25\text{pp}$；$R=24 \to 0.90\text{pp}$（未修前）；$R=32 \to 0.76\text{pp}$；$R=48 \to 0.37\text{pp}$。
  - 要依靠当前代码自然收敛到 $<0.1\text{pp}$，需 $R \ge 120$（网格量超数千万单元，完全不可行）。
- **根治方案（坐标域外扩）的预期行为：**
  若将物理盒子严格固定为 $[0, 2\pi k]^3$（严格 $k$ 个完整周期），将数据采样域向外扩张 $[-\text{margin}\cdot\Delta x, 2\pi k + \text{margin}\cdot\Delta x]$，且 `solve_level` 仅在目标盒体内采样：
  - **实测验证**：$R=24$ 时孔隙率偏差直接从 $+0.90\text{pp}$ 暴跌至 **$-0.02\text{pp}$**（提升 45 倍精度），且外包围盒严格对齐 $[12.57, 12.57, 12.57]$。

### 关注点 ②：pymeshfix 兜底对几何的改动量级与报告机制

#### 1. 实测改动量级数据（基准算例）
在基准参数（$k=2, R=24, p=0.60$）下，各阶段几何演变实测统计如下：

| 处理阶段 | 面数 Faces | 体积 Volume | 水密性 Watertight | 变化说明 |
|---|---|---|---|---|
| **原始 Marching Cubes** | 54,428 | 610.2228 | **True** (拓扑闭合) | 拓扑闭合但含 4942 个二面角=0 的共面折叠/重叠退化面 |
| **trimesh.process(validate=True)** | 49,486 | 610.2228 | **False** (开孔破坏) | 删除了 4942 个退化面，导致网格边缘开孔，破坏水密性！ |
| **pymeshfix.clean_from_arrays** | 47,556 | 606.5181 | **True** (重新封闭) | 进一步移除了 1930 个面，体积削减 **3.705 mm³ (-0.61%)**，控制台告警 `MeshFix could not fix everything` |

#### 2. 工程风险评估
1. **边界截面侵蚀**：pymeshfix 主要在盒子外壁与 TPMS 相交的折痕交线处进行布尔补孔与缝合，直接削减了外壁平面的真实截面面积。对于力学压缩仿真，顶底压板的实际承载接触面积被低估约 $0.6\%$，反演弹性模量会人为产生轻微虚高。
2. **静默失效隐患**：当前 `p0_generate.py` 对 `pymeshfix` 的调用无任何量化报告（未统计被修改的面数、体积丢失率 $\Delta V / V$）。若在极限孔隙率（如 $p \ge 0.85$）或复杂骨架下 `pymeshfix` 出现大面积侵蚀甚至切断局部薄壁支柱，当前脚本完全无法捕获。

#### 3. 建议整改措施
- 增加三阶段几何体检审计报告（输出 Raw MC $\to$ Process $\to$ Meshfix 各阶段的面数、体积与水密状态）。
- 设定安全阈值：当 $|\Delta V / V_0| > 1.0\%$ 或删除面占比 $> 15\%$ 时，触发显式 `[WARN]` 甚至 `[FAIL]` 阻断，提醒上游调整分辨率或边界外扩方式，严禁无感知"强行缝合"。

### 关注点 ③：盒 SDF 交线附近三角形质量对 C3D10 网格质量的影响

#### 1. 劣质三角形产生的几何根源
在 `p0_generate.py` 中：
$$g(x,y,z) = \max(c - f(x,y,z), \; \text{box\_sdf}(x,y,z))$$
- TPMS 等值面 $c - f = 0$ 与盒子外壁 $\text{box\_sdf} = 0$ 相交时，其交线在空间中呈现为一条尖锐的 $C^0$ 连续折痕（梯度 $\nabla g$ 不连续，法向突变约 $90^\circ$）。
- Marching Cubes 算法在非平滑场 $\max(A, B)$ 的交线穿过的体素网格内进行三线性插值时，由于不同角点分别由 $c-f$ 与 $\text{box\_sdf}$ 主导，算法在立方体边上截出的求根点极度接近体素顶点或另一边交点。
- **实测空间分布统计**：
  - 全局共 54,428 个三角形，长宽比（Aspect Ratio）$>10$ 的三角形高达 **6,900 个（占全局 12.68%）**；长宽比 $>50$ 的严重畸变三角形达 **5,266 个**！
  - 空间坐标关联度分析表明：**72.7% 的畸变三角形（5,014 / 6,900）精确分布在距离盒壁 $\le 1.5 \Delta x$ 的交线边界带内！**

#### 2. 对 Gmsh HXT discrete 划网与 C3D10 体单元质量的直接影响
在 `p1_mesh.py` 中，采用 `discrete` 路线：
```python
gmsh.model.mesh.createTopology()
...
gmsh.option.setNumber("Mesh.Algorithm3D", 10) # HXT
gmsh.model.mesh.generate(3)
gmsh.model.mesh.setOrder(2)
```
- **表面网格冻结机理**：`createTopology()` 将导入的 STL 三角面片作为固定的三维体网格边界。HXT 四面体剖分器以这些三角面片作为基底向内部推进。**劣质表面三角面直接作为三维四面体的一个底面被强行保留下来**。
- **体单元质量实测（Gmsh 4.15 API 探针实测）**：
  - 四面体总数：206,961 个 C3D10 单元。
  - 最小单元体积：**$2.418 \times 10^{-9}\text{ mm}^3$**（与中位数 $2.8 \times 10^{-3}\text{ mm}^3$ 相差整整 **6 个数量级**！典型扁平针状 sliver 单元）。
  - 有符号反条件数（minSICN）：最小值仅为 **$1.038 \times 10^{-3}$**（理想正四面体为 1.0，工程通用合格红线通常为 $0.1$）。
  - 劣质单元数：minSICN $< 0.05$ 的单元达 **884 个**；$\gamma$ 质量因子 $< 0.05$ 的单元达 **971 个**。

#### 3. 对下游 ABAQUS 求解的潜在工程危害
1. **Static 弹性段（Phase 2 关键路径）**：
   - **刚度矩阵病态**：长宽比 $>100$ 的 C3D10 单元在弹性力学刚度矩阵中对应极大的主对角与非对角系数比，导致矩阵条件数急剧恶化，ABAQUS 求解器极易报出 `NUMERICAL SINGULARITY` 或 `HIGH CONDITION NUMBER` 警告，累积数值浮点误差。
   - **伪应力集中与虚高**：二阶单元中间节点位移梯度在扁平单元上极易出现数值振荡，高斯积分点上的 Mises 应力与主应力会出现虚假奇点，严重污染材料屈服判定。
   - **反力提取失真**：若顶面/底面反力是通过边界节点集合 `*NODE OUTPUT, RF` 累加提取（兼容平台 `fit-batch.mjs` 契约），交线附近的病态单元会引入局部的接触力数值噪声。
2. **Explicit 准静态压缩（若后续扩展至压溃段）**：
   - **时间步崩溃（CFL 灾难）**：稳定时间步 $\Delta t_{\text{cr}} \le \frac{L_{\text{min}}}{c_d}$。特征尺度 $L_{\text{min}} \sim 10^{-4}\text{ mm}$ 将导致显式步长跌至 $10^{-11}\text{ s}$ 级别，求解耗时成百倍上升，即便引入质量缩放（Mass Scaling）也会因边界极小单元过量加重而破坏动能比 `ALLKE/ALLIE < 5%`。
   - **自接触穿透**：折痕处凹凸不平的边界微三角形对通用接触（General Contact）极不友好，易引发接触力震颤和节点穿透。

## 三、代码级其他重大数值与工程健壮性缺陷（超预期发现）

在深度代码走查与格式转换探针实测中，反重力发现了两个**会导致 Phase 2 ABAQUS 求解直接报错退出（FATAL ERROR）的重大缺陷**：

### 缺陷 A（致命）：`p1_mesh.py` 未过滤 2D 表面单元，导致 `.inp` 混入 `CPE6` 平面应变单元
- **现场实测证据**：
  在 `p1_mesh.py` 第 53~59 行：
  ```python
  mesh = meshio.read(msh_path)
  tet10 = [c for c in mesh.cells if c.type == "tetra10"]
  ...
  out_inp = msh_path.with_suffix(".inp")
  meshio.write(out_inp, mesh, file_format="abaqus") # 致命：传入的是包含全单元的 mesh！
  ```
  Gmsh 导出的 `.msh` 文件中不仅包含体单元 `tetra10`（206,961 个），还包含用于定义表面边界的 2D 面单元 `triangle6`（47,556 个）。
  `meshio` 内部映射规则为：`triangle6 -> CPE6`（6 节点平面应变单元），`tetra10 -> C3D10MH`。
  因此导出的 `gyroid_k2_p60.inp` 中同时包含了 `*ELEMENT, TYPE=CPE6` 和 `*ELEMENT, TYPE=C3D10MH`！
- **后果**：
  在三维空间模型中，ABAQUS 严禁二维平面应变单元与三维实体单元混合使用，`Abaqus datacheck` 会立即抛出致命语法错误：
  `***ERROR: ELEMENT TYPE CPE6 CANNOT BE USED IN A THREE-DIMENSIONAL MODEL`。
  *(注：该项在 `plans/2026-10-28 §2 & §3 坑 4` 已明确预警"过滤混入的 2D 面单元"，但脚本实现时遗漏了过滤步骤)*。

### 缺陷 B：`p1_mesh.py` 导出的实体单元类型被 meshio 写死为 `C3D10MH`（杂交单元）
- **现象**：
  `meshio` 的 Abaqus writer 将 `tetra10` 硬编码映射为 `C3D10MH`（带静水压力自由度的修正杂交二次四面体）。
- **后果**：
  在金属等压缩弹性分析中，杂交单元额外引入了拉格朗日乘子压力自由度，造成非必要的计算内存与求解耗时开销；且与标准线弹性 Static 分析中预期的 `C3D10`（位移型）或接触优化的 `C3D10M` 不符。建议在写入后或写入时对类型做显式规范化。

### 缺陷 C：`p1_mesh.py` 中 `lmax` 参数完全未传给 Gmsh（死参数）
- **现象**：
  `p1_mesh.py` 的 CLI 接收 `--lmax 0.5`，函数签名声明了 `make_mesh(stl: Path, lmax: float)`，但在函数体内**没有任何一行代码将 `lmax` 设置进 Gmsh**（未调用 `gmsh.option.setNumber("Mesh.MeshSizeMax", lmax)`）。用户传任何 `--lmax` 均静默无效。

### 缺陷 D：`verify_tet10` 验证门禁过于宽松
- **现象**：
  当前只检查行列式 $vol6 > 0$（无翻转负体积）。对于 $vol6 = 10^{-12}$、SICN $= 10^{-3}$ 的极端劣质 sliver 单元直接放行。必须在门禁中加入最小特征长度比或反条件数警告。
