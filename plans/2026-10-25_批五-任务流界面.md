# 批五：任务流界面（审查"以任务组织入口"方向首档）

## 问题定义

审查观察（TPMS-实用性审查与改进建议 §修复之后值得投入的产品改进 第 1 行）：功能链条
设计→候选→制造检查→导出→试验分析分散在 4 个分组面板 + 工具栏浮层菜单中，新用户不知道
"下一步做什么"。验收愿景：未参与开发的使用者在无口头指导下完成一次预定交付。

## 物理模型与研究目标

无物理模型（纯 UI 组织层）。目标 = 给完整交付流程一条**连续入口**：每步可一键跳到
对应面板，且状态可见（已完成 ✓ / 因设计变更而过期 ! / 未做），让"当前设计是否已检查、
已导出"不靠记忆。

## 我的假设与归因猜想

1. 审查痛点的主要成分是**导航缺失**而非功能缺失——五步功能全部已存在（批一~批四刚好
   补齐了导出门与制造检查），缺的是把它们串起来的组织层。因此首档做导航+状态层，
   不动任何功能内核，即可通过"无指导完成交付"的验收。
2. 状态语义里最有价值的是 **stale（过期）**：制造检查/导出针对的是"当时的设计"，用户
   改参数后旧结果静默失效是可追溯闭环（审查方向 3）的隐性断点。用设计指纹
   `geometryStateKey()`（main.ts 既有，=cacheKey+meshContTag）在显示时校验即可，
   无需侵入 rebuild 管线。

## 需要的素材与数据

- [x] UI 结构与跳转机制（ls-jump scrollTo / handleExport / bindManufacturingCard / bindParetoCard / bindExperimentalFit 源码已读）

## 方案（最小改动：一张卡 + 四个标记点）

### UI 结构决策（记录，欢迎改）

任务流卡放 **controls 侧栏顶部（ls-jump 之下、grp-geometry 之上）**，不放 viewer：
审查原文"逐步展开相关设置"指向侧栏叙事；viewer 侧改动风险高（浮层多）。
侧栏首屏已有一行 ls-jump，再加一行五步条（高约 56px）可接受。

### 1. index.html

- 任务流卡 `div.taskflow#taskflow`：标题行"交付任务流"+五步横条（grid 5 列），
  每步 = 编号 + 名称 + 状态徽章（✓ / ! / 空）。**不用 `.sect` 类、不用 `data-jump`
  属性**——规避 ui_jump 两个硬断言（.panel.controls .sect 总数=30、.ls-jump [data-jump]=4）。
- 五步 data-step：design / candidate / mfg / export / analyze。
- 给制造几何检查 sect 加 `id="sect-mfg"`、试验曲线反演 sect 加 `id="sect-expfit"`
  （Pareto 已有 sect-pareto；构型组直接滚 grp-geometry）。
- CSS 融入现有内嵌样式块（.taskflow/.tf-step/.tf-badge done|stale，深浅双主题）。

### 2. main.ts（bindTaskFlowCard + 模块级 taskFlow 状态）

- 状态：`{ mfgSig, exportSig, paretoDone, expfitDone }`（前两者存设计指纹字符串）。
- 点击行为：
  - design → rail 滚到 grp-geometry 顶；
  - candidate → 滚到 sect-pareto 并 open；
  - mfg → 滚到 sect-mfg 并 open；
  - export → `btn-export.click()`（导出中心浮层直接展开，无需滚动）；
  - analyze → 滚到 sect-expfit 并 open。
- 状态刷新 refreshTaskFlow()：
  - ①恒 ✓（默认设计即就绪）；
  - ②paretoDone（26 族扫描与当前设计参数无关，不挂指纹）；
  - ③mfgSig === 当前指纹 → ✓；不匹配 → !（stale，title="设计已变更，请重跑"）；
  - ④exportSig 同理；
  - ⑤expfitDone（试验数据是外部输入，设计变更不失效——卡片说明披露）。
- 四个标记点：bindManufacturingCard 成功路径末尾记 mfgSig；handleExportInner
  `flashToast('已导出')` 后记 exportSig；bindParetoCard 首次生成前沿记 paretoDone；
  bindExperimentalFit 出结果记 expfitDone。
- 刷新时机：标记点各调一次 + scheduleRebuild 防抖回调起点调一次（设计变更→③④转 stale）。

### 3. 验收探针 probe_taskflow.mjs（一次性，.verify 不入 CI）

1. 卡在位且五步计数=5、不用 .sect 类（ui_jump 计数不受扰——独立断言 30 不变）；
2. 点 mfg 步 → rail 滚动 + sect-mfg open；
3. 跑制造检查（gyroid 默认）→ ③徽章 ✓；
4. 改孔隙率（75→70 触发 rebuild）→ ③转 !（stale）；
5. 点 export 步 → 导出中心浮层 .show 可见；
6. 0 pageerror / 0 console.error（慢 runner 分级口径）。

### 4. 验证标准

- tsc 零错；规范 cwd 构建（bash -c "cd … && node node_modules/vite/bin/vite.js build"）
  且产物带 license 头部戳；本地 diff dist docs/platform 零差异后同步部署产物。
- 本地全量 48 门（含 ui_jump 30 计数不变）+ probe_taskflow 全过。
- 提交推送，CI+Pages 同 HEAD 双绿。

## 范围外（明确不做）

- 不做向导式分步表单/任务持久化（localStorage 任务列表）——审查"逐步展开"由既有
  details 折叠+跳转满足；持久化等真实使用者反馈后再议。
- 不动五步功能的任何内核（导出门/制造检查算法/Pareto/expfit 逻辑零变更）。
- 不修预先存在的 sgroup 头部手写数字（12/10/1/5 与实际 13/11 不符）——与任务流无关，
  仅在此登记。
- 工艺阈值标定、S1 真实试样闭环（等用户侧素材）。
