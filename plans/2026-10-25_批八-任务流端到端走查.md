# 批八：任务流五步端到端走查（审查 row 1 验收方式机械化首档）

## 问题定义

审查 row 1 验收方式="让未参与开发的使用者在无口头指导下完成一次预定交付；记录卡住的
位置、操作时间和输出错误"。批五~七探针均单卡单测，**跨步状态流转从未连跑**：
采用后的设计 → 制造检查 → 交付包 → 试验分析是否连贯未知；且采用路径（Pareto 前沿点
写回）的交付包 manifest 尺寸契约是批六新代码无探针。

## 物理模型与研究目标

无新物理（验证批次）。目标=一次 browser 会话连走五步，机械记录每步 PASS/卡点/耗时，
产出走查报告供用户审阅（AI 代跑≠真人验收，报告中如实披露该局限）。

## 我的假设与归因猜想

1. 前沿点点击在批五 probe 里因 playwright 每次往返 ~1.2s 而绕开——改为**页面内合成
   MouseEvent 序列**（单次 evaluate 内循环派发 mousemove+click），576 网格点亚秒完成，
   hover 20px 容差+网格步距覆盖的几何论证不变。
2. 扫掠命中的前沿点族不可控（fcks 在扫描域内且结构性拒产）——命中后读 document.title，
   命中 fcks 则继续扫掠取下一个可产族（前沿多点，后续点击=改采用）。
3. 采用设计的交付包导出走 ensureExportGradeGeometry（schwarz/gyroid 显示档直通免升档），
   manifest.sizeContract 应记 periods=3+总宽=3×单胞（批六 effWidthMm 消费链）。

## 方案

1. probe_taskflow_e2e.mjs（可重复，不入 CI）：单会话五步——
   ①设计：boot 默认 gyroid → 稳定读数；
   ②比较候选：任务流卡 ② 跳转 → Pareto 扫描 → 页面内扫掠采用（避开 fcks）→ 断言
   sw-value=3×单胞+title 换族；
   ③制造检查：任务流卡 ③ → btn-mfg → 四指标文本 + ③ 徽章 ✓；
   ④导出交付：任务流卡 ④ → 导出中心 → createObjectURL 拦截抓 ZIP → node 解析 →
   manifest 尺寸契约/条目齐备断言（**新覆盖**）；
   ⑤试验分析：任务流卡 ⑤ → DataTransfer 注入合成 CSV → E* 出数 + ⑤ 徽章 ✓；
   每步计时 + 0 pageerror（分级口径）。
2. 走查报告 agent_memory/taskflow-e2e-2026-10-25.md（供用户审阅；含局限披露）。
3. 发现断链则修复重跑；全绿则本批纯验证（代码零改动）。

  提交推送 CI+Pages 同 HEAD 绿。
